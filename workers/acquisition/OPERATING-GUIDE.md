# Codistan Acquisition — Operating Guide

This guide uses the only supported operator vocabulary: **Codistan Acquisition**.

## Install or upgrade

From the repository folder, double-click:

`START-HERE-ACQUISITION.cmd`

The installer:

1. verifies the release manifest;
2. backs up protected local state;
3. installs into `app-current` while retaining `app-previous`;
4. refreshes stable unpacked extension folders;
5. starts all three collectors;
6. validates their health;
7. verifies that captured records, dedupe fingerprints and sync configuration were preserved.

Do not delete `%LOCALAPPDATA%\Codistan\Acquisition` during an upgrade.

## Chrome extensions

Use exactly two unpacked extension folders:

- `%LOCALAPPDATA%\Codistan\Acquisition\extensions\upwork`
- `%LOCALAPPDATA%\Codistan\Acquisition\extensions\linkedin`

The LinkedIn extension contains both warm LinkedIn capture and Sales Navigator campaign capture.

After install or rollback:

1. open `chrome://extensions`;
2. enable Developer mode;
3. load or reload the two folders above;
4. confirm Upwork extension `1.1.0`;
5. confirm LinkedIn & Sales Navigator extension `1.5.0`.

## Start, check and diagnose

Use the neutral shortcuts or commands:

- `START-ACQUISITION.cmd`
- `CHECK-ACQUISITION.cmd`
- `DIAGNOSE-ACQUISITION.cmd`
- `OPEN-ACQUISITION-REVIEW.cmd`

Health endpoints:

- Upwork: `http://127.0.0.1:8765/health`
- LinkedIn warm: `http://127.0.0.1:8775/health`
- Sales Navigator: `http://127.0.0.1:8785/health`

The watchdog restarts the supervisor when a managed collector exits. It will not take over a port owned by an unrelated process.

## Prospect Desk synchronization

Run `CONFIGURE-PROSPECT-DESK-SYNC.cmd` once with the approved production endpoint and ingest token. The configuration remains at:

`%LOCALAPPDATA%\Codistan\Acquisition\config\prospect-desk-sync.json`

Do not paste the token into screenshots, issue comments or diagnostics.

## Daily operator flow

1. Check collector health.
2. Open only approved Upwork, LinkedIn or Sales Navigator searches.
3. Review captured evidence and qualification locally or in Prospect Desk.
4. Confirm account/person identity before cold outreach preparation.
5. Assign an owner, task and due date.
6. Prepare and approve outreach in the human-controlled workbench.
7. Perform any external action manually on the relevant platform.
8. Record the exact action and outcome in Prospect Desk.
9. Review source/campaign/channel quality in `/commercial-analytics`.

## Rollback

Run:

`ROLLBACK-ACQUISITION.cmd`

Rollback swaps `app-current` and `app-previous`, refreshes the two stable extension folders, starts all collectors and verifies protected-state hashes. It does not roll back or delete captured records, dedupe fingerprints or Prospect Desk sync configuration.

After rollback, reload both unpacked extensions in Chrome.

## Diagnostics and support package

`DIAGNOSE-ACQUISITION.cmd` writes a redacted diagnostics package under the local state root. It may contain:

- release and component versions;
- collector health and port ownership;
- application-slot status;
- protected-state file counts and hashes;
- configuration presence without endpoint tokens;
- runtime log tails.

It must not contain opportunity bodies, cookies, passwords, sync tokens or browser storage.

## Live acceptance before release

The release candidate must not be flattened into `main` until a real accepted record has been verified from:

- Upwork;
- LinkedIn warm content;
- Sales Navigator;
- Prospect Desk after upgrade and rollback.

Record the results in the live-acceptance checklist generated by diagnostics. Package CI alone is not live acceptance.
